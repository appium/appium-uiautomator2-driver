    Migrating from UiScrollable and UiSelector

    Many tests use -android uiautomator expressions not to find elements, but to scroll: new UiScrollable(new UiSelector().scrollable(true).instance(0)).scrollIntoView(...). Google is going to remove UiScrollable and UiSelector from the UiAutomator framework, after which these locators stop working. The driver logs a warning, once per session, if it sees one. This guide shows what to use instead.

    Requirements

    The scrolling features described here are available since driver version 10.3.0. With older versions, mobile: scroll only supports the accessibility id, class name and -android uiautomator strategies, and mobile: scrollGesture requires an element or an area. The -android predicate string and -android class chain strategies, which the guide recommends for finding elements, are available since driver versions 10.2.0 and 10.1.0. The Java snippets use java-client 11. With java-client 10, cast the elements to RemoteWebElement instead of AppiumWebElement to get their identifiers. The approach is the same for any client, only the way of calling mobile: commands differs.

    Why migrate¶

    • UiScrollable is going away, and so are the locators built on UiSelector, including the ones the driver generates for the css selector strategy.
    • It can be slow. On an emulator, scrolling a strip of 30 tabs from the first tab to the 28th took about 41 seconds with UiScrollable and about 28 seconds with mobile: scroll, and to the 10th tab about 19 and 7 seconds (medians of 2 or 3 runs).
    • It hides failures. If the chain of a UiScrollable locator has a setter (setMaxSearchSwipes, setAsHorizontalList, ...) and the target is not on the screen yet, the lookup returns the scrollable container instead of the target, even if the target does not exist, instead of failing with "no such element".
    • scrollIntoView() checks the current viewport first. If the target is not there, it scrolls towards the beginning by up to the swipe limit before searching forward, so a long list may only be rewound partway, and there is no parameter to change that.

    What replaces what¶

    Legacy Use instead
    UiScrollable(...).scrollIntoView(selector), scrollTextIntoView(text), scrollDescriptionIntoView(text) mobile: scroll with the -android predicate string, -android class chain, id, accessibility id or xpath strategy
    getChildByText(...), getChildByDescription(...), getChildByInstance(...) Find the child inside the view
    scrollForward(), scrollBackward() mobile: scrollGesture
    scrollToEnd(n), flingToEnd(n), scrollToBeginning(n), flingToBeginning(n) Scroll to the end or to the beginning
    setAsHorizontalList() direction of mobile: scroll
    setMaxSearchSwipes(n) maxSwipes of mobile: scroll
    setSwipeDeadZonePercentage(p) Gestures on elements keep a 10% margin from the edges of the element. Use an element, or an area that is inset from the screen edges.
    ViewPager and carousels mobile: swipeGesture
    Plain UiSelector lookups A predicate string or class chain locator, or a simple strategy

    Replacing UiSelector lookups¶

    Prefer the -android predicate string and -android class chain strategies to xpath. They are evaluated directly on the accessibility tree, without building the page source of the whole application. In the measurements, a single element is found about as fast as with UiSelector and twice as fast as with XPath, and the lookups of several elements are faster than with both. They also work with mobile: scroll. Use id, accessibility id or class name if the element is identified by that attribute alone, and XPath only if the other strategies cannot express the condition, for example a step to the parent or a sibling.

    UiSelector Predicate string Other strategies
    .text("A") text == 'A'
    .textContains("A") text CONTAINS[c] 'A'
    .textStartsWith("A") text BEGINSWITH[c] 'A'
    .textMatches("A.*") text MATCHES '(?s)A.*'
    .description("A") content-desc == 'A' accessibility id
    .resourceId("pkg:id/a") resource-id == 'pkg:id/a' id
    .className("android.widget.Button") class == 'android.widget.Button' class name
    .scrollable(true) scrollable == true
    .clickable(true), .checked(true), ... clickable == true, checked == true
    several conditions clickable == true AND text CONTAINS[c] 'A'
    .instance(n) **/*[`<predicate>`][n + 1] (class chain)
    .childSelector(...) **/*[`resource-id == 'list'`]/**/*[`text == 'A'`] (class chain)

    The ...Contains and ...StartsWith methods of UiSelector are not case sensitive, hence the [c] modifier, which does the same. The ...Matches methods must match the whole value, and . also matches line breaks, hence the (?s) flag, the predicate operator MATCHES also has to match the whole value. The description... methods behave the same way for content-desc. The exact matches, text() and description(), are case sensitive. A predicate string cannot select by position or in relation to other elements, which is what the class chain syntax is for. Both are described in the Class Chain Locator Strategy guide.

    The same lookups with xpath, for the cases that need it:

    UiSelector XPath
    .text("A") //*[@text='A']
    .textContains("A") //*[contains(lower-case(@text), 'a')] (XPath 2)
    .textStartsWith("A") //*[starts-with(lower-case(@text), 'a')] (XPath 2)
    .textMatches("A.*") //*[matches(@text, '^A.*$', 's')] (XPath 2)
    .description("A") //*[@content-desc='A']
    .resourceId("pkg:id/a") //*[@resource-id='pkg:id/a']
    .className("android.widget.Button") //android.widget.Button
    .scrollable(true) //*[@scrollable='true']
    .clickable(true), .checked(true), ... //*[@clickable='true'], //*[@checked='true']
    .instance(n) (<expression>)[n + 1]
    .childSelector(...) A nested path, for example //*[@resource-id='list']//*[@text='A']

    The XPath above lower-cases the attribute and expects a lower-case literal for the ...Contains and ...StartsWith methods, and uses the anchors and the s flag for ...Matches. XPath 2 is the default, unless the enforceXPath1 setting is enabled.

    Choosing the tool¶

    mobile: scroll mobile: scrollGesture W3C actions
    Scrolls until an element is visible yes no, one swipe per call no, one swipe per call
    Tells if more content is available no yes, returns false at the end no
    Can scroll several pages in one call yes, up to maxSwipes yes, percent above 1 no
    Vendor extension yes yes no
    Control over the exact path and speed no speed only full

    Prefer mobile: scroll to reach an element, mobile: scrollGesture for a fixed amount of scrolling or your own stop condition, and W3C actions if you cannot use mobile: commands.

    Recipes¶

    Scroll until an element is visible¶

    mobile: scroll scrolls a view with gestures and looks for the element inside of it after each swipe. It stops when the element is visible, when the end of the content is reached, or after maxSwipes swipes (30 by default). If the element is not found, the command fails with "no such element".

    /** Scrolls the first scrollable view until an element satisfying the predicate is visible. */
static void scrollTo(AndroidDriver driver, String predicate) {
    driver.executeScript("mobile: scroll", Map.of(
            "strategy", "-android predicate string",
            "selector", predicate));
}

/** Scrolls the given view from its beginning, using at most 10 swipes. */
static void scrollTo(AndroidDriver driver, WebElement view, String predicate) {
    driver.executeScript("mobile: scroll", Map.of(
            "elementId", ((AppiumWebElement) view).getId(),
            "strategy", "-android predicate string",
            "selector", predicate,
            "fromStart", true,
            "maxSwipes", 10));
}

    For example, scrollTo(driver, "text == 'Settings'") replaces scrollIntoView(new UiSelector().text("Settings")).

    • Without elementId, the first scrollable view on the screen is scrolled. Pass the view when there are several scrollable views, such as a drawer and a list, and prefer a view found by its resource id to (//*[@scrollable='true'])[1].
    • The search goes down by default. It does not return to the beginning of the content unless fromStart is true, so use fromStart if the element might be above the current position.
    • The strategies -android predicate string, -android class chain, id, xpath, accessibility id and class name are supported. -android uiautomator is supported too, but deprecated. Prefer the first two to xpath, as described above: the element is looked up after every swipe, so the speed of the lookup adds up.

    Warning

    Eventually, all locators based on the -android uiautomator strategy will fail, not only the ones used for scrolling.

    Scroll horizontal lists¶

    A HorizontalScrollView is scrolled to the right by default, so the code above works for tab strips. Other horizontal containers, for example a horizontal RecyclerView, need a direction:

    /** Scrolls a horizontal view that is not a HorizontalScrollView, for example a RecyclerView. */
static void scrollRightTo(AndroidDriver driver, WebElement view, String predicate) {
    driver.executeScript("mobile: scroll", Map.of(
            "elementId", ((AppiumWebElement) view).getId(),
            "strategy", "-android predicate string",
            "selector", predicate,
            "direction", "right"));
}

    Scroll to the end or to the beginning¶

    mobile: scrollGesture returns true if more content is available, and a percent above 1 scrolls that many pages, stopping at the end:

    /** Values of "percent" above 1 scroll that many pages and stop at the end of the content. */
static void scrollToEnd(AndroidDriver driver, WebElement view) {
    driver.executeScript("mobile: scrollGesture", Map.of(
            "elementId", ((AppiumWebElement) view).getId(),
            "direction", "down",
            "percent", 50));
}

static void scrollToBeginning(AndroidDriver driver, WebElement view) {
    driver.executeScript("mobile: scrollGesture", Map.of(
            "elementId", ((AppiumWebElement) view).getId(),
            "direction", "up",
            "percent", 50));
}

    Your own search loop¶

    If you need your own stop condition, for example a text that appears after a scroll, call mobile: scrollGesture in a loop. Set the implicit wait to zero while the loop is running, because otherwise every lookup that finds nothing takes as long as the implicit wait, and restore it afterwards:

    /** The same as scrollTo, but with your own stop condition and no dependency on the strategies above. */
static WebElement scrollIntoView(AndroidDriver driver, WebElement view, By target, int maxSwipes) {
    // Every lookup that finds nothing would otherwise take as long as the implicit wait
    Duration implicitWait = driver.manage().timeouts().getImplicitWaitTimeout();
    driver.manage().timeouts().implicitlyWait(Duration.ZERO);
    try {
        List<WebElement> found = view.findElements(target);
        for (int i = 0; i < maxSwipes && found.isEmpty(); i++) {
            boolean canScrollMore = (Boolean) driver.executeScript("mobile: scrollGesture", Map.of(
                    "elementId", ((AppiumWebElement) view).getId(),
                    "direction", "down",
                    "percent", 0.7));
            found = view.findElements(target);
            if (!canScrollMore) {
                break;
            }
        }
        if (found.isEmpty()) {
            throw new NoSuchElementException("Cannot scroll to " + target);
        }
        return found.get(0);
    } finally {
        driver.manage().timeouts().implicitlyWait(implicitWait);
    }
}

    Find a child of the view¶

    getChildByText(childPattern, text) found a child of the scrollable view that matches childPattern and contains the text, and scrolled to it. It returns that child, for example the list row, not the nested text view. Scroll first, then look for the child with a nested XPath. Quotes.escape() makes the text safe for labels that contain quotes:

    /** Replaces UiScrollable.getChildByText(): returns the child of the given class that has the text itself or contains it. */
static WebElement childByText(WebElement view, String childClassName, String text) {
    return view.findElement(AppiumBy.xpath(
            ".//" + childClassName + "[descendant-or-self::*[@text=" + Quotes.escape(text) + "]]"));
}

    For example, childByText(list, "android.widget.LinearLayout", "Settings") returns the row that has a Settings label. Use .//*[@text=...] instead if you need the label itself.

    Page through a carousel¶

    UiScrollable cannot scroll views that are not reported as scrollable, such as a ViewPager. Swipe them instead:

    /** Pages a carousel or a ViewPager to the next page. */
static void nextPage(AndroidDriver driver, WebElement pager) {
    driver.executeScript("mobile: swipeGesture", Map.of(
            "elementId", ((AppiumWebElement) pager).getId(),
            "direction", "left",
            "percent", 0.75));
}

    W3C actions¶

    If mobile: commands are not available, for example because a grid does not allow them, swipe with a pointer sequence. The duration of the move sets the speed: a very short move turns into a fling and overshoots. Get the coordinates from the element, and stay inside of it, away from the screen edges.

    /** Moves the finger from the bottom to the top of the view, which scrolls the content down. */
static void swipeUp(AndroidDriver driver, WebElement view) {
    Rectangle rect = view.getRect();
    int x = rect.x + rect.width / 2;
    int startY = rect.y + (int) (rect.height * 0.8);
    int endY = rect.y + (int) (rect.height * 0.2);
    PointerInput finger = new PointerInput(PointerInput.Kind.TOUCH, "finger");
    Sequence swipe = new Sequence(finger, 0)
            .addAction(finger.createPointerMove(Duration.ZERO, PointerInput.Origin.viewport(), x, startY))
            .addAction(finger.createPointerDown(PointerInput.MouseButton.LEFT.asArg()))
            .addAction(new Pause(finger, Duration.ofMillis(100)))
            .addAction(finger.createPointerMove(Duration.ofMillis(600), PointerInput.Origin.viewport(), x, endY))
            .addAction(finger.createPointerUp(PointerInput.MouseButton.LEFT.asArg()));
    driver.perform(List.of(swipe));
}

    W3C actions do not report whether more content is available, so check the result of the swipe yourself, for example by looking for the element after each swipe.

    Things to know¶

    • Speed. One scroll gesture takes about a second and a half, plus the time to look for the element. Searching the far end of a long list can take half a minute, so give mobile: scroll a realistic maxSwipes, and scroll the list that contains the element, not the whole screen.
    • Screen edges and gesture navigation. A swipe that starts on the edge of the screen can be taken by the system for the back or home gesture. Gestures on elements keep a 10% margin, but a gesture on an area does not: keep the area inside of the screen. An area that covers the whole display is clamped to its last pixel, which is still an edge.
    • Animations. A click right after a scroll can miss if the list is still moving. Keep disableWindowAnimation enabled or wait for the element to stop moving.
    • Direction. down and right move towards the end of the content, like scrollForward(). The finger moves the other way.
    • Stale elements. Elements that scrolled out of the screen can disappear from the hierarchy of recycling views such as RecyclerView, so look them up again after scrolling.

    Troubleshooting¶

    Symptom Reason and fix
    "There are no scrollable elements on the current display" The screen has nothing the accessibility service reports as scrollable. Pass the view you want to scroll, or use mobile: swipeGesture or W3C actions.
    "Cannot scroll to ..." The element was not found before the end of the content or maxSwipes. Check the locator in the page source, raise maxSwipes, set fromStart if the element can be above the current position, or set direction for a horizontal view.
    The wrong view is scrolled Several views are scrollable. Pass the view as elementId.
    Nothing happens, scrollGesture returns false The view is already at the end in that direction, or the area is outside of the screen.
    A horizontal list does not scroll Only a HorizontalScrollView is horizontal by default. Set direction.
    A swipe opens a list item A horizontal swipe on a vertical list can end as a click on the row. Swipe along the axis of the view.
    The element is found, but the click does nothing The list was still moving. See "Animations" above.
