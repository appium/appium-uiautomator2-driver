    Settings

    The UiAutomator2 driver exposes various settings through Appium's Settings API.

    actionAcknowledgmentTimeout¶

    Type Default
    long 3000

    Maximum number of milliseconds to wait for an acknowledgment of a generic UI Automator click action. Calls Configurator.setActionAcknowledgmentTimeout() under the hood.

    allowInvisibleElements¶

    Type Default
    boolean false

    Whether to include elements that are not visible to the user (whose displayed attribute is false) in the XML source tree.

    alwaysTraversableViewClasses¶

    Type Default
    string ""

    Comma separated list of Android element classes, whose visible/invisible state should be ignored by the UiAutomator2 server during the application source tree traversal.

    The default logic for the UI tree traversal (controlled by the allowInvisibleElements setting) is to stop recursing when an invisible node is found. However, with certain Jetpack Compose classes (e.g. androidx.compose.ui.viewinterop.ViewFactoryHolder), invisible parent nodes may have visible child nodes. See this Google issue and this UiAutomator2 server issue for more details.

    This setting only affects the XPath lookup and the page source buildup. The list of classes may also include glob patterns, e.g. androidx.compose.ui.viewinterop.*,android.widget.ImageButton.

    Available since driver version 5.0.3.

    currentDisplayId¶

    Type Default
    integer 0 (Display.DEFAULT_DISPLAY)

    Identifier of the display that should be used for driver actions such as retrieving screenshot, finding elements, etc. Available values can be retrieved using the mobile: listDisplays execute method, or by running adb shell dumpsys display (search for mDisplayId).

    If set to -1, the display is reset to the default one.

    Refer to the Multi-Window Testing guide for detailed usage information.

    Available since driver version 4.2.0.

    deferAccessibilityCacheReset¶

    Type Default
    boolean false

    Whether the UiAutomator2 server should clear the accessibility cache for element/source lookups only if a relevant UI-change AccessibilityEvent has been observed since the last reset. By default, the cache is cleared for every element/source lookup, which prevents the cache from going stale, but may result in significant memory usage under sustained lookups.

    See this UiAutomator2 server issue for more details.

    Available since driver version 8.1.0.

    disableIdLocatorAutocompletion¶

    Type Default
    boolean false

    Whether to disable automatic prefixing of resource-id-based element selectors with the application package name.

    Internal Android standards expect each element resource identifier to be prefixed with the <packageName>:id/ string. This is done to ensure uniqueness of each identifier. However, this rule is not strictly enforced, and different development frameworks either ignore this or leave this behavior up to the developer: for example, in Jetpack Compose, using the testTag modifier attribute with testTagsAsResourceId allows setting an arbitrary string without the prefix rule. Interoperability with UiAutomator also explains how to set it.

    By default, the driver adds the above prefix automatically to all unprefixed resource-id locators, but this setting allows disabling this behavior.

    Available since driver version 2.0.6.

    elementResponseAttributes¶

    Type Default
    string name,text

    Comma-separated list of element attribute names to be included into element search responses. The following values are supported: name, text, rect, enabled, displayed, selected, attribute/<element_attribute_name>.

    Has no effect if the shouldUseCompactResponses setting is set to true.

    enableMultiWindows¶

    Type Default
    boolean false

    Whether to include all windows that the user can interact with (e.g. an on-screen keyboard) while building the application page source. By default, only the focused active application window is included in the page source.

    Refer to the Multi-Window Testing guide for detailed usage information.

    enableNotificationListener¶

    Type Default
    boolean true

    Whether to enable the listener for new toast notifications and allow toast message texts to be included into the application page source. By default, this listener is enabled and tracks toast messages for up to 3500 ms after their expiration.

    enableTopmostWindowFromActivePackage¶

    Type Default
    boolean false

    Whether to select the application window with the highest Z-order as the active window. By default, the driver selects the focused window, which generally also has the highest Z-order, but this may not be the case for multi-window apps, or devices with multiple displays.

    Refer to the Multi-Window Testing guide for detailed usage information.

    Available since driver version 2.25.2.

    enforceXPath1¶

    Type Default
    boolean false

    Whether to enforce usage of XPath1 for XPath-based element lookup.

    The default built-in XPath2 interpreter is based on the PsychoPath implementation, which is identical to an XPath1 interpreter for most cases, but more sophisticated locators may run into issues due to different behavior. This setting can be used to try to workaround such issues by enforcing XPath1 usage (whose implementation is a part of the Android platform itself).

    This setting is primarily relevant for driver versions 7.5.1 or earlier, since the issues that resulted in the introduction of this setting were solved in version 7.5.2, as a result of vendoring the PsychoPath library.

    ignoreUnimportantViews¶

    Type Default
    boolean false

    Whether to enable compression of the application source layout hierarchy.

    If enabled, the layout hierarchy derived from the accessibility framework will only contain nodes that are important for UI Automator testing. Any unnecessary surrounding layout nodes that make viewing and searching the hierarchy inefficient are removed.

    includeA11yActionsInPageSource¶

    Type Default
    boolean false

    Whether to include the actions element attribute in the application source. This attribute value could be huge if elements in the page source have a lot of actions, which could affect the performance of page source generation.

    Available since driver version 4.0.0.

    includeExtraRenderingInfo¶

    Type Default
    boolean false

    Whether to include the text-size and text-unit element attributes in the application source. Retrieval of these attributes has a slight effect on the performance of page source generation.

    Available since driver version 6.7.10.

    includeExtrasInPageSource¶

    Type Default
    boolean false

    Whether to include the extras element attribute in the application source. This attribute value could be huge if elements in the page source have a lot of extras, which could affect the performance of page source generation.

    Available since driver version 2.1.0.

    keyInjectionDelay¶

    Type Default
    integer 0

    Delay in milliseconds between key presses, used when inputting text.

    limitXPathContextScope¶

    Type Default
    boolean true

    Whether to limit the context scope of XPath-based element lookups to the parent element.

    Due to historical reasons, by default, the driver limits the scope of element context-based searches to the parent element. This means that a request like findElement(By.xpath, "//root").findElement(By.xpath, "./..") would always fail, because the driver only collects descendants of the root element. Disabling this setting causes the retrieved page source to includes the entire page source, resulting in the aforementioned query to no longer fail.

    Disabling this setting nonetheless requires caution with other context-based queries - for example, a request like findElement(By.xpath, "//root").findElement(By.xpath, "//element") would ignore the current context and search for element through the whole page source. In such cases it is recommended to use the dot (.) notation: findElement(By.xpath, "//root").findElement(By.xpath, ".//element").

    Available since driver version 2.0.2.

    mapTestTagToResourceId¶

    Type Default
    boolean false

    Whether to map the testTag semantic property of Jetpack Compose elements onto their resource-id attribute.

    Enabling this setting mirrors the behavior of Compose's own testTagsAsResourceId, which can otherwise only be toggled from within the app's own composable tree. The mapping is consistently applied to element attribute retrieval, page source/XPath generation, and id-based element lookups. Unlike the disableIdLocatorAutocompletion setting, bare testTag values are matched as-is, without automatically prepending the application package name.

    Available since driver version 8.4.0.

    mjpegBilinearFiltering¶

    Type Default
    boolean false

    Whether to apply bilinear filtering to the MJPEG screenshot broadcaster's resize algorithm. Enabling this flag may improve the quality of the resulting scaled bitmap, but may introduce a small performance hit.

    Refer to the MJPEG guide for more details.

    mjpegScalingFactor¶

    Type Default
    integer 50

    The percentage value to which the screenshots generated by the MJPEG screenshot broadcaster are downscaled. Must be in range 1..100. By default, screenshots are downscaled to half of their original size.

    Refer to the MJPEG guide for more details.

    mjpegServerFramerate¶

    Type Default
    integer 10

    Maximum screenshots per second taken by the MJPEG screenshot broadcaster. Must be in range 1..60.

    Refer to the MJPEG guide for more details.

    mjpegServerPort¶

    Type Default
    integer 7810

    The port on the device under test to start the MJPEG screenshot broadcaster on. Must be in range 1024..65535.

    On the host machine, the forwarded MJPEG server port can be configured using the appium:mjpegServerPort capability.

    Refer to the MJPEG guide for more details.

    mjpegServerScreenshotQuality¶

    Type Default
    integer 50

    The percentage value of the quality to which the screenshots generated by the MJPEG screenshot broadcaster are compressed. Must be in range 1..100. By default, screenshots are compressed to half of their original quality.

    Refer to the MJPEG guide for more details.

    normalizeTagNames¶

    Type Default
    boolean false

    Whether to apply Unicode-to-ASCII normalization of element class names, when converting them to XML tag names in the application page source. This setting can be useful if the application under test has some Unicode class names which cannot be used as XML tag names, due to known bugs in Android's XML DOM parser implementation.

    scrollAcknowledgmentTimeout¶

    Type Default
    long 200

    Maximum number of milliseconds to wait for an acknowledgment of a UiScrollable scroll action. Calls Configurator.setScrollAcknowledgmentTimeout() under the hood.

    serverPort¶

    Type Default
    integer 6790

    The port on the device under test to start the UiAutomator2 server on. Must be in range 1024..65535.

    On the host machine, the forwarded UiAutomator2 server port can be configured using the appium:systemPort capability.

    shouldUseCompactResponses¶

    Type Default
    boolean true

    Whether to enable compact responses for element search requests. If disabled, responses will include the attributes specified by the elementResponseAttributes setting.

    shutdownOnPowerDisconnect¶

    Type Default
    boolean true

    Whether to shutdown the UiAutomator2 server if the device under test is disconnected from a power source and remains on battery power.

    simpleBoundsCalculation¶

    Type Default
    boolean false

    Whether to calculate element bounds as absolute values, instead of always checking if the element may be covered by other elements and is therefore partially hidden.

    Enabling this setting improves the performance of generating the application page source, but decreases precision of element bounds. Use with care.

    snapshotMaxDepth¶

    Type Default
    integer 70

    The maximum retrieved depth of the application page source tree. Lower values can help speed up source retrieval and prevent out of memory or timeout errors such as #12545 or #12892. Must be in range 1..500.

    Available since driver version 2.27.0.

    trackScrollEvents¶

    Type Default
    boolean true

    Whether to track all scroll events for the purpose of calculating the value of elements' contentSize attribute. Disabling this setting may speed up all scrolling actions.

    useResourcesForOrientationDetection¶

    Type Default
    boolean false

    Whether to detect device orientation using Android's Configuration state, instead of calculating it from the device rotation state. This setting can be useful for certain devices where the default rotation approach does not work properly, and erroneously detects a portrait orientation as landscape (and vice versa).

    waitForIdleTimeout¶

    Type Default
    long 10000

    Maximum timeout in milliseconds to wait until the application user interface enters an idle state.

    By default, the UiAutomator2 server performs this wait for all core UI Automator objects (except UiDevice) before searching for the element matching the object's locator. Reducing this value may help in mitigating long delays when interacting with elements.

    waitForSelectorTimeout¶

    Type Default
    long 10000

    Maximum timeout in milliseconds to wait for an element match, when searching using the -android uiautomator locator strategy.

    Since content in the user interface is dynamic, sometimes an element may not be immediately visible, and will not be detected by a selector. This timeout adds an extra wait during search, until at least one match is found.

    This setting only affects element searches using the -android uiautomator location strategy.

    wakeLockTimeout¶

    Type Default
    long 86400000 (24 hours)

    Maximum timeout in milliseconds for how long the UiAutomator2 server should prevent the device under test from going to sleep during an automated test.

    Setting this value to zero forces the server to release the wake lock.
