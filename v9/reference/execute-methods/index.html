    Execute Methods

    The UiAutomator2 driver provides various custom execute methods based on the standard Execute Script endpoint. Use the following examples in order to invoke them from your client code:

    var result = driver.executeScript("mobile: <methodName>", Map.ofEntries(
    Map.entry("arg1", "value1"),
    Map.entry("arg2", "value2")
    // you may add more pairs if needed or skip providing the map completely
    // if all arguments are defined as optional
));

    const result = await driver.executeScript('mobile: <methodName>', [{
    arg1: "value1",
    arg2: "value2",
}]);

    result = driver.execute_script('mobile: <methodName>', {
    'arg1': 'value1',
    'arg2': 'value2',
})

    result = @driver.execute_script 'mobile: <methodName>', {
    arg1: 'value1',
    arg2: 'value2',
}

    object result = driver.ExecuteScript("mobile: <methodName>", new Dictionary<string, object>() {
    {"arg1", "value1"},
    {"arg2", "value2"}
}));

    Session¶

    mobile: scheduleAction¶

    Adds a new action to the list of scheduled actions. Refer to the Scheduled Actions guide for more details.

    Available since driver version 2.29.6.

    Parameters¶

    Name
    Type
    		 Description
    name string Unique name of the action
    steps Array<ActionStep> One or more action steps to execute. See below for a detailed structure. Steps are executed in sequential order. All steps are executed even if any of them fails. The execution is considered failed if at least one step fails.
    maxPass? integer Number of successful action invocations after which it should automatically stop repeating
    maxFail? integer Number of unsuccessful action invocations after which it should automatically stop repeating
    times? integer Number of times the action should execute within a single invocation. Set to 1 by default
    intervalMs? integer Interval in milliseconds between subsequent action invocations. Set to 1000 by default
    maxHistoryItems? integer Maximum number of action invocation entries stored in history. All entries are sorted in descending order by action execution timestamp. If the number of entries exceeds this value, the oldest entry is deleted. Setting this parameter to a large value may cause out of memory issues. Set to 20 by default.

    Each item in the steps array (ActionStep) must be an object with the following properties:

    Name
    Type
    		 Description
    type string Type of the step. Supported values are gesture, source, and screenshot.
    name string Name of the step. Does not need to be unique.
    payload ActionStepPayload Payload of the step. See below for a detailed structure.

    The contents of payload (ActionStepPayload) must be an object, and its properties depend on the value of type:

    The object properties generally matches the property set for mobile: clickGesture, mobile: doubleClickGesture, or mobile: longClickGesture.

    Name
    Type
    		 Description
    subtype string Can be set to click, longClick or doubleClick
    elementId? string Element to use as the click origin
    x? float X offset from the element origin or screen
    y? float Y offset from the element origin or screen
    locator? Record<string, string> Object with the strategy and selector keys. Useful for clicking dynamic elements
    duration? float Click duration (only for longClick subtype)
    Name Type Description
    subtype string Must be set to xml
    Name Type Description
    subtype string Must be set to png

    Response¶

    null

    mobile: getActionHistory¶

    Returns the execution history for an action. Refer to the Scheduled Actions guide for more details.

    Available since driver version 2.29.6.

    Parameters¶

    Name Type Description
    name string Name of the action to retrieve history for

    Response¶

    ActionHistory - an object with the following properties:

    Name
    Type
    		 Description
    repeats integer Number of times this action has been repeated so far
    stepResults Array<ActionInvocation> List of recorded action invocations, sorted by execution timestamp in descending order. See below for a detailed structure. The maximum length of the list is limited by maxHistoryItems.

    Each item in stepResults array (ActionInvocation) is itself an array of objects, where each object has the following properties:

    Name
    Type
    		 Description
    name string Name of the step as per its original ActionStep
    type string Type of step as per its original ActionStep
    timestamp integer Unix timestamp in milliseconds of the step execution start time
    passed boolean Whether the step passed
    result any Result of the step. Depends on the step type and subtype, and can be null. Always null if passed is false.
    exception Record<string, string> or null Object with the name, message and stacktrace properties of the raised exception. Always null if passed is true.

    mobile: unscheduleAction¶

    Removes an action from the list of scheduled actions and returns its execution history. Refer to the Scheduled Actions guide for more details.

    Available since driver version 2.29.6.

    Parameters¶

    Name Type Description
    name string Name of the action to remove from scheduling

    Response¶

    ActionHistory

    Device Under Test¶

    mobile: shell¶

    Executes the specified adb shell command on the device under test. The adb_shell insecure feature must be enabled.

    Parameters¶

    Name
    Type
    		 Description
    command string Shell command name to execute
    args? Array<string> Additional arguments to pass to the command. Keys and values should be provided as separate strings.
    timeout? integer Command timeout in milliseconds. An error is thrown if the command blocks for longer than this timeout. Set to 20000 by default
    includeStderr? boolean Whether to include stderr stream into the returned result. Set to false by default

    Response¶

    string or Record<string, string> - contents of the returned stdout, or if includeStderr is true, an object with the stdout and stderr keys and their respective values.

    An error is thrown if the command exits with a non-zero return code, with the error message matching the command's stderr.

    mobile: deviceInfo¶

    Retrieves information about the device under test.

    Response¶

    Record<string, any> - mapping of device properties to their values. The following properties are included:

    Name
    		 Description
    androidId Device identifier (ANDROID_ID)
    manufacturer Device manufacturer (MANUFACTURER)
    model Device model (MODEL)
    brand Device brand (BRAND)
    apiVersion Major Android version (VERSION.SDK_INT)
    platformVersion User-visible platform version (VERSION.RELEASE)
    carrierName Network carrier name (TelephonyManager.getNetworkOperatorName())
    realDisplaySize Real size of the default display, in <width>x<height> format (based on Display.getRealSize())
    displayDensity Display density in Density Independent Pixel units (based on DisplayMetrics.density)
    networks Array of objects, where each object contains information related to an available network type (based on ConnectivityManager.getAllNetworks(), ConnectivityManager.getNetworkInfo(network), and ConnectivityManager.getNetworkCapabilities(network))
    locale System locale (Locale.getDefault())
    timeZone System timezone (TimeZone.getDefault())
    bluetooth Object with Bluetooth-related information, such as its state (BluetoothAdapter.getState())

    mobile: batteryInfo¶

    Retrieves battery-related information for the device under test.

    Response¶

    Record<string, any> - object with battery-related information, with the following properties:

    Name Type Description
    level float Current battery level fraction in range [0..1], where 1.0 means 100% charge. Set to -1 if the actual value cannot be retrieved from the system. (BatteryManager.EXTRA_LEVEL and BatteryManager.EXTRA_SCALE)
    state integer Current battery state, matching the value of a supported BATTERY_STATUS constant of the BatteryManager class. Set to -1 if the actual value cannot be retrieved from the system. (BatteryManager.EXTRA_STATE)

    mobile: getDeclaredOrientation¶

    Retrieves the manifest-declared screen orientation of the current foreground activity (ActivityInfo.screenOrientation).

    This reflects the value set in the activity's AndroidManifest.xml file (android:screenOrientation), which may differ from any runtime orientation overrides (e.g. Activity.setRequestedOrientation()) or the current display orientation (PORTRAIT/LANDSCAPE) returned by the Get Orientation API.

    Available since driver version 8.5.0.

    Response¶

    string | null - the name of the declared screen orientation constant (e.g. SCREEN_ORIENTATION_PORTRAIT), or null if the current activity is unknown or its manifest orientation cannot be resolved

    mobile: listDisplays¶

    Retrieves a list of all displays available on the device under test. Under the hood, calls DisplayManager.getDisplays() for physical displays, and adb shell dumpsys SurfaceFlinger --displays for virtual displays.

    Refer to the Multi-Window Testing guide for detailed usage information.

    Available since driver version 6.6.0.

    Response¶

    Array<Record<string, any>> - list of display information objects, where each object contains the following properties:

    Name
    Type
    		 Description
    id integer Logical identifier of the display. Used by the currentDisplayId setting.
    name string or null Name of the display
    physicalId string or null Physical identifier of the display. Returned as a string to avoid JavaScript number precision issues with large values. Can be used by the mobile: screenshots method.
    virtualId string or null Virtual identifier of the display. Only set for virtual displays. Can be used by the mobile: screenshots method.
    metrics DisplayMetrics Display metrics such as size and density. See below for a detailed structure.
    isDefault boolean Whether this is the default display

    The metrics item (DisplayMetrics) is an object with the following properties:

    Name
    		 Type Description
    widthPixels integer Display width in pixels
    heightPixels integer Display height in pixels
    density float Display density (logical density factor). This is the scaling factor for the display.
    densityDpi integer Display density in DPI (dots per inch)
    scaledDensity float Scaled density factor for fonts. Usually the same as density, but may be adjusted by the user's font size preference.
    xdpi integer Exact physical pixels per inch of the screen in the X dimension
    ydpi integer Exact physical pixels per inch of the screen in the Y dimension

    mobile: listWindows¶

    Retrieves a list of all windows on the device under test.

    For devices running Android 11 (R / API level 30) or newer, this method retrieves all windows on all available displays (using UiAutomation.getWindowsOnAllDisplays()). For older devices, only windows from the default display are retrieved (using UiAutomation.getWindows()).

    Refer to the Multi-Window Testing guide for detailed usage information.

    Available since driver version 6.5.0.

    Parameters¶

    Name
    Type
    		 Description
    filters? WindowFilters Conditions for filtering the returned list of windows. Specified conditions are applied using AND logic (all must match). See below for a detailed structure.
    skipScreenshots? boolean Whether to skip taking screenshots for each window. Screenshots are only supported since Android 14 (U / API level 34). Set to false by default. Setting this to true can improve performance.

    The filters property (WindowFilters) is an object with the following properties:

    Name
    		 Type Description
    packageName? string Name of the application package which the window should belong to. Can be specified as a glob pattern.
    windowId? integer Window identifier
    displayId? integer Logical display identifier
    physicalDisplayId? string Physical display identifier
    type? integer Window type, matching the value of a supported AccessibilityWindowInfo TYPE_ constant
    title? string Window title. Can be specified as a glob pattern.
    layer? number Z-order layer value of the window
    isAccessibilityFocused? boolean Whether the window has accessibility focus
    isActive? boolean Whether the window is active
    isFocused? boolean Whether the window has input focus
    isInPictureInPictureMode? boolean Whether the window is in picture-in-picture mode

    Response¶

    Array<Record<string, any>> - list of window information objects, where each object contains the following properties:

    Name
    Type
    		 Description
    windowId integer or null Identifier of the window. Set to null if the identifier cannot be determined.
    displayId integer Logical identifier of the display that owns this window
    physicalDisplayId string or null Physical identifier of the display that owns this window. Returned as a string to avoid JavaScript number precision issues with large values.
    virtualDisplayId string or null Virtual identifier of the display that owns this window. Only set for virtual displays.
    rect Record<string, integer> Object with window bounds, containing the left, top, right, bottom properties
    packageName string Name of the application package which the window belongs to
    screenshot string or null Base64-encoded PNG screenshot of the window. Only supported since Android 14 (U / API level 34) if skipScreenshots is set to false.
    type integer Window type, matching the value of a supported AccessibilityWindowInfo TYPE_ constant
    title string or null Window title
    layer number Z-order layer value of the window
    isAccessibilityFocused boolean Whether the window has accessibility focus
    isActive boolean Whether the window is active
    isFocused boolean Whether the window has input focus
    isInPictureInPictureMode boolean Whether the window is in picture-in-picture mode

    mobile: viewportRect¶

    Retrieves the viewport bounds of the current window. This is equivalent to calling the standard Get Window Rect endpoint and subtracting the dimensions of the device status and navigation bars.

    Response¶

    Record<string, integer> - an object with the following properties:

    Name Type Description
    left integer X-axis offset of the viewport
    top integer Y-axis offset of the viewport
    width integer Viewport width
    height integer Viewport height

    mobile: getDisplayDensity¶

    Retrieves the density of the current display in DPI.

    Available since driver version 2.21.0.

    Response¶

    integer - the display density in DPI

    mobile: getSystemBars¶

    Retrieves properties of various bars in the system UI.

    Available since driver version 2.21.0.

    Response¶

    Record<string, Record<string, any>> - mapping of system bar names to their properties. The following system bar names are included:

    • statusBar
    • navigationBar

    All system bars include the following properties:

    Name Type Description
    visible boolean Whether the bar is visible
    x integer Left X coordinate of the bar. Could be 0 if the bar is not visible
    y integer Top Y coordinate of the bar. Could be 0 if the bar is not visible
    width integer Bar width. Could be 0 if the bar is not visible
    height integer Bar height. Could be 0 if the bar is not visible

    mobile: getPerformanceData¶

    Retrieves performance data about the given Android subsystem. The data is parsed from the output of the dumpsys utility.

    Available since driver version 2.24.0.

    Parameters¶

    Name
    		 Type Description
    packageName string Name of the package identifier to fetch the data for
    dataType string Subsystem name to return the data for. Supported values can be retrieved using the mobile: getPerformanceDataTypes method.

    Response¶

    Array<Array<any>[]> - table formatted as an array of arrays, where the first subarray represents column names, and the following subarrays represent data for those columns. The returned columns and their data depend on the specified dataType.

    For example, a response for the cpuinfo datatype could look as follows: 

    [
  [user, kernel],
  [0.9, 1.3]
]

    mobile: getPerformanceDataTypes¶

    Retrieves supported performance data types, which can be used as the dataType argument for the mobile: getPerformanceData method.

    Available since driver version 2.24.0.

    Response¶

    Array<string> - list of supported data types

    mobile: startLogsBroadcast¶

    Starts a websocket server for broadcasting Android logcat logs, using the host and port of the Appium server. The resulting endpoint is /ws/session/:sessionId:/appium/logcat. Broadcasting can be stopped using the mobile: stopLogsBroadcast execute method.

    The method will return immediately if the web socket is already listening. Each listener will receive logcat log lines as soon as they are visible to Appium.

    Refer to Using Mobile Execution Commands to Continuously Stream Device Logs with Appium for more details.

    Consider using log broadcast via BiDi over this extension.

    Response¶

    null

    mobile: stopLogsBroadcast¶

    Stops the logcat websocket server previously started using mobile: startLogsBroadcast. The method will return immediately if no websocket server is running.

    Refer to Using Mobile Execution Commands to Continuously Stream Device Logs with Appium for more details.

    Consider using log broadcast via BiDi over this extension.

    Response¶

    null

    mobile: resetAccessibilityCache¶

    Resets the accessibility cache on the device under test. This method can be useful if the cache becomes stale and needs to be refreshed in order to reflect the current UI state.

    The driver automatically resets this cache before any element lookup, as well as before retrieving the page source, but in case the application under test has highly dynamic elements, it may be beneficial to explicitly call this method, in order to avoid stale reference errors or interaction issues.

    Note that this method also waits until the app under test becomes idle, so it may affect test performance if called too often under dynamic circumstances.

    Available since driver version 6.4.1.

    Response¶

    null

    mobile: getUiMode¶

    Retrieves the value for the specified device appearance mode. Only supported since Android 10 (Q / API level 29). Calls adb shell cmd uimode under the hood.

    Available since driver version 2.34.0.

    Parameters¶

    Name Type Description
    mode string Appearance mode to check. Supported values are night and car.

    Response¶

    string - value of the specified appearance mode

    mobile: setUiMode¶

    Sets the device appearance mode. Only supported since Android 10 (Q / API level 29). Calls adb shell cmd uimode under the hood.

    Available since driver version 2.34.0.

    Parameters¶

    Name Type Description
    mode string Appearance mode to set. Supported values are night and car.
    value string Value of the specified mode. Supported values are either yes, no, auto, custom_schedule, and custom_bedtime (for night mode), or yes and no (for car mode).

    Response¶

    null

    mobile: screenshots¶

    Retrieves a screenshot of all device displays. Only supported since Android 10 (Q / API level 29).

    This method uses physical or virtual display IDs, which are different from logical display IDs used by the currentDisplayId setting. Physical/virtual display IDs can be obtained using the mobile: listDisplays or mobile: listWindows execute methods, or the adb shell dumpsys SurfaceFlinger --display-id command.

    Available since driver version 2.29.0. Virtual display IDs are supported since driver version 6.6.2.

    Parameters¶

    Name
    		 Type Description
    displayId? integer or string Physical or virtual display identifier to take a screenshot for. By default, all available displays are used. An error is thrown if a display with the specified ID does not exist.

    Response¶

    Record<string, Record<string, any>> - a map of display identifiers to their properties. Each set of properties contains the following:

    Name Type Description
    id string Display identifier
    name string Display name
    isDefault boolean Whether this display is the default one
    payload string Base64-encoded PNG screenshot of the display

    mobile: viewportScreenshot¶

    Retrieves a screenshot of the current viewport. This is equivalent to calling the standard Get Screenshot endpoint and cropping it to the visible viewport (returned by mobile: viewportRect).

    Response¶

    string - a base64-encoded PNG image of the current viewport

    mobile: startScreenStreaming¶

    Starts an MJPEG server for broadcasting the screen of the device under test. The adb_screen_streaming insecure feature must be enabled, and the host machine must have GStreamer installed and available on PATH, along with the gst-plugins-base, gst-plugins-good, gst-plugins-bad and gst-libav packages.

    Broadcasting can be stopped using the mobile: stopScreenStreaming execute method. Repeated calls to this method have no effect unless the previous streaming session is stopped.

    For the built-in device MJPEG stream (no GStreamer), see the MJPEG guide.

    Parameters¶

    Name
    		 Type Description
    width? integer Scaled width of the device screen. Set to the actual device screen width by default.
    height? integer Scaled height of the device screen. Set to the actual device screen height by default.
    bitRate? integer Bitrate of the video, in bits per second. Set to 4000000 (4 Mbps) by default.
    host? string IP address/host name to start the MJPEG server on. Set to 127.0.0.1 by default. Can be set to 0.0.0.0 to broadcast on all available network interfaces.
    pathname? string URL path on which the MJPEG server should be accessible. By default, all pathnames on the given host/port combination are accessible. Must begin with a forward slash (/).
    port? integer Port number to start the MJPEG server on. Set to 8093 by default.
    tcpPort? integer Port number to start the internal TCP MJPEG broadcast on. Always starts on the loopback interface (127.0.0.1). Set to 8094 by default.
    quality? integer Quality of the broadcasted images. Must be in the range [1, 100], where 100 indicates the best quality. Set to 70 by default.
    considerRotation? boolean Whether to increase the broadcast dimensions to fit both landscape and portrait orientations. Should be set to true if the device orientation will be changed during the broadcast. Set to false by default.
    logPipelineDetails? boolean Whether to include GStreamer pipeline event logs into the standard log output. Can be useful for debugging purposes. Set to false by default.

    Response¶

    null

    mobile: stopScreenStreaming¶

    Stops the MJPEG screen broadcasting server previously started using mobile: startScreenStreaming. The method will return immediately if no streaming server is running.

    For the built-in device MJPEG stream (no GStreamer), see the MJPEG guide.

    Response¶

    null

    mobile: startMediaProjectionRecording¶

    Starts recording the device screen and audio using Android's Media Projection API. Only supported since Android 10 (Q / API level 29). Recording can be stopped using the mobile: stopMediaProjectionRecording execute method.

    Available since driver version 2.4.0.

    Parameters¶

    Name
    		 Type Description
    resolution? string Resolution of the resulting video, formatted as <width>x<height>. Supported values are 1920x1080, 1280x720, 720x480, 320x240 and 176x144. Set to the greatest supported device resolution by default (usually 1920x1080).
    priority? string Priority of the recorder process, which could be adjusted in case of performance drops. Supported values are high, normal and low. Set to high by default.
    maxDurationSec? integer Maximum recording time in seconds. Set to 900 (15 minutes) by default.

    Starts the specified app activity using adb shell am start-activity.

    Parameters¶

    Name
    Type
    		 Description
    intent? string Full name of the activity intent to start
    user? integer or string ID of the user to start the activity for. By default, the default user is used.

    stop? boolean Whether to stop the target app before starting the activity. Unset by default.
    windowingMode? integer Windowing mode to launch the activity intent into. Supported values can be found in the Android source code as WINDOWING_MODE_ constants.
    activityType? integer Activity type to launch the intent as. Supported values can be found in the Android source code as ACTIVITY_TYPE_ constants.

    uri? string Activity intent URI
    mimeType? string Activity intent MIME type
    identifier? string Activity intent identifier
    categories? string or Array<string> One or more activity intent categories. Refer to the Android Intent documentation for a list of possible values (prefixed with CATEGORY_).
    component? string Activity intent component
    package? string Activity intent package name
    display? integer or string Display identifier to launch the activity intent on
    extras? ActivityExtras Extra activity intent arguments. See below for expected structure

    sn Null (only the key is required; the value should be omitted)

    i Integer
    l Long integer
    f Float

    ia String of comma-separated integers
    ial String of comma-separated integers
    la String of comma-separated long integers
    lal String of comma-separated long integers
    fa String of comma-separated floats
    fal String of comma-separated floats
    sa Comma-separated strings (commas that are part of the strings themselves should be escaped)
    sal Comma-separated strings (commas that are part of the strings themselves should be escaped)
